# ARCHITECTURE — FinRepGYM

> Записка об устройстве среды (основа для «Записки о дизайне» при сдаче).
> Версия документа: 0.2, 20.11.2026. Статус: контракт, все 4 типа ошибок, адаптер
> оценщика и опубликованные определения проверок (20.11) реализованы и проверены.

## 1. Четыре силы, из которых следует всё

1. **Детерминизм.** (seed, config, версия, последовательность действий) → байт-в-байт
   одинаковые записи, переходы и награды.
2. **Изоляция плоскостей.** Плоскость агента и плоскость оценщика общаются только через
   узкий канал «действие → наблюдение».
3. **Отсутствие утечек.** Закрытый эталон не может попасть в наблюдение, лог, текст
   ошибки, путь или объяснение награды.
4. **Честная награда.** Только поля находок и доказательств; подсказок по ходу нет.

## 2. Подсистемы

| Подсистема | Файл | Ответственность |
|---|---|---|
| Генератор | `src/audit_env/generator.py` | скрытая история → документы → причинные мутации → `truth.json` / `provenance.json` |
| Среда | `src/audit_env/env.py` | контракт `reset/step`, 5 действий, лимиты, режимы train/eval, жизненный цикл |
| Оценщик | `src/audit_env/matcher.py` + `reward.py` | нормализация, взаимно однозначное сопоставление, P/R/F1, терминальная награда |
| Политики | `src/audit_env/policies.py` | 4 адаптера: random, reconciliation, mark-all, oracle + раннери `run_episode` |
| Хранилище эпизодов | `episodes/{train,dev}/<id>/{open,closed}` | физическое разделение открытой и закрытой зон |
| Проверка | `tests/` | 4 слоя тестов, повторяющих блоки проверок жюри |

## 3. Плоскости и потоки информации

```
[Генератор] ──► [Хранилище: open/ + closed/]
                      │
                      ▼
[Среда reset/step] ◄── действия ── [Политика/агент]
        │  наблюдения                    ▲
        ▼                                │
[trajectories.jsonl]   [Оценщик: matcher → F1 → награда] ──► отчёт жюри (вне процесса)
```

* Открытая зона: `manifest.json`, `ledger.csv`, `invoices.jsonl`, `payments.jsonl`,
  `fx.csv`, `policy.json` — **плюс их копии в первом наблюдении** (manifest и policy:
  это открытые файлы, утечки нет).
* Закрытая зона: `truth.json`, `provenance.json`, зерно генерации. Доступны только
  методам `evaluator_report()` / `evaluator_truth()`; в `info` возвращаются лишь
  `mode` и `steps_used`.

## 4. Конвейер генерации (5 стадий)

1. **Скрытая история.** Контрагенты, счета, платежи; каждое событие даёт **пару** строк
   журнала → `Σдебет = Σкредит` истинно по построению. Закладываются отвлекающие случаи.
2. **Проверка чистого состояния.** Баланс книг и согласованность дебиторки с документами.
   Несовпадение → генератор останавливается (это брак, не «сложность»).
3. **Документы.** Выгрузка шести открытых файлов по форматам спеки.
4. **Каузальные мутации.** Ошибка вносится после проверки; каждая фиксируется как
   «причинное изменение» со снимками «до/после» и порождает **вычислимое по открытым
   файлам расхождение** (дубль → `Σдебет − Σкредит = −сумма`; переезд платежа → завышение
   дебиторки внутри периода = сумма платежа).
5. **Независимая верификация.** Пересчёт расхождений из открытых файлов обязан совпасть
   с `truth.json`, иначе эпизод не создаётся. Затем манифест, эталон, провенанс.

## 5. Жизненный цикл эпизода

`Сброс → Расследование → Завершён`

* **Сброс** пересобирает всё состояние; в наблюдении ровно четыре блока: задача,
  manifest, краткая политика, остаток бюджета. Зерна в наблюдении нет.
* **Расследование:** каждый шаг тратит единицу бюджета; награда строго 0; наблюдение —
  только запрошенные записи **или** результат **или** ограниченная ошибка **и**
  остаток шагов. Подсказок о правильности нет.
* **Завершение:** `submit` → `terminated` (+ награда в train, ноль в eval); исчерпание
  100 шагов или 60 с → `truncated` с **пустым итоговым ответом**, который оценивается
  как молчание (иначе тайм-аут становится способом избежать штрафа — решение
  зафиксировано, режим настраивается); неверная структура `submit` → завершение с
  наградой −1 и записью в журнал оценщика.

## 6. Действия и защиты

| Действие | Защита |
|---|---|
| `list_records` | страница ≤ 50, курсор-смещение стабилен (таблицы неизменны), превышение лимита — ошибка |
| `get_record` / `get_document` | неизвестный id → ограниченная ошибка без списка валидных id; шаг расходуется |
| `calculator` | только десятичные числа и `+ - * /`; проверка структуры выражения; десятичная арифметика; без имён, вызовов, файлов |
| `submit` | ≤ 30 находок, ≤ 10 id доказательств, ≤ 1000 символов объяснения, сверка `episode_id` |

Нет: shell, SQL, файловой системы, сети.

## 7. Сопоставление и награда (опубликовано)

* **Канонизация:** тип — точное совпадение; `affected_ids` — множество строк, сортировка;
  валюта — верхний регистр; сумма — целое в минимальных единицах.
* **TP** требует одновременно: тип + равенство канонических наборов записей + валюта +
  сумма в пределах `amount_tolerance_minor` + хотя бы один **полный** допустимый набор
  доказательств (включение множеств).
* **Назначение** жадное в порядке подачи; повтор по занятой ошибке → FP; несопоставленные
  находки → FP; непокрытые эталоны → FN.
* **Краевые случаи F1:** пустой эталон и пустые находки → 1; эталон пуст, находки есть → 0;
  нулевой знаменатель P/R → 0.
* **Награда:** `clip(2·F1 − 1 − 0.002·inspection_steps, −1, 1)`, только терминальная.

## 8. Модель атак и защиты

| Атака | Защита |
|---|---|
| пометить всё | FP считаются один к одному → F1 падает → −1 |
| угадать id | нужен полный комплект: тип+записи+валюта+сумма+полные доказательства |
| доказательства «на словах» | проверка включением в допустимый набор |
| дубль находки | назначение одно-к-одному → второй дубль FP |
| убедительный текст | награда поле объяснения не читает (тест) |
| экономия шагов | 0.002 за шаг; тест подтверждает малость различия |
| тайм-аут вместо молчания | пустой ответ при `truncated` оценивается |
| утечка через ошибки/пути/логи/награду | наблюдение собирается из трёх разрешённых блоков; сканер траектории на запрещённые маркеры |

## 10. Эксплуатация и границы

* Python 3.11+, **только стандартная библиотека**, без сети/платных API/GPU.
* Лимиты эпизода: 100 шагов, 60 с; железо проверки: 2 CPU, 4 ГБ RAM, 1 ГБ на решение.
* Вне области: обучение весов (необязательно, баллов не даёт), реальные финансовые
  данные, утверждения об улучшении модели без контролируемого сравнения на отложенных
  данных, UI-претензии.
