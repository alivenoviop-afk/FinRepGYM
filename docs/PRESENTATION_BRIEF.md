## 2. Структура презентации: 8 слайдов

### Слайд 1. Заголовок
- `FinRepGYM` — RL-среда для дообучения ИИ-аудитора (синтетика, офлайн, MIT)
- Репозиторий: **github.com/alivenoviop-afk/FinRepGYM** (со зелёным CI)
- «Симулятор, а не агент» — одна строка под заголовком.

### Слайд 2. Задача и рамки (1 минута)
- Агент изучает записи → 5 инструментов → отправляет выводы с доказательствами → среда оценивает.
- **Вне рамок (и мы это честно показываем):** обучение весов, платёжные приложения, чат-боты, один отчёт, реальные данные, сеть/GPU при проверке.
- *Реплика:* «Среда задаёт задания и ставит оценки. Веса она никогда не обновляет — это требование ТЗ.»

### Слайд 3. Как создаётся эпизод (1 минута)
- Правильная бухгалтерия (пары строк, равенство по построению) → документы → **внесение ошибки с записью "что именно сломали"** → независимая верификация расхождения.
- Отвлекающие случаи: возвраты, разбитые платежи, повторяющиеся суммы.
- *Реплика:* «Эталон описывает реальное расхождение, а не подозрительную строку — иначе это было бы враньё, а не сложность».

### Слайд 4. Что прячется (1 минута)
Таблица:

| Тип | Как выглядит |
|---|---|
| `duplicate_entry` | одна операция записана дважды |
| `partial_allocation` | платёж распределён не полностью |
| `fx_rate` | конвертация по курсу не той даты |
| `period_cutoff` | операция отнесена не в тот период |

+ **2 сценария взаимодействия**: S1 «курс + граница», S2 «частичный платёж в другой валюте на границе» — **обе ошибки делят один платёж**, наивный детектор теряет вторую.

### Слайд 5. Контракт и изоляция (40 секунд)
- `reset/step` в стиле Gymnasium, 5 действий, только чтение, 100 шагов, 60 с, страница ≤50.
- Открытая зона (6 файлов) vs закрытая (`truth`, `provenance`, seed) — **физически разделены**.
- Награда 0 при исследовании; в режиме проверки награда остаётся у оценщика.
- *Реплика:* «В наблюдении ровно три вещи: запрошенные записи, результат или ограниченная ошибка, остаток шагов. Никакого shell, SQL и интернета».

### Слайд 6. Награда и атаки (1 минута)
- `clip(2·F1 − 1 − 0.002·inspection_steps, −1, 1)`; P/R/F1 с краевыми случаями.
  `inspection_steps` — шаги до `submit` (submit не в штрафе).
- Таблица **по данным диагностики** (P и R усреднены по 20 эпизодам, включая 3 чистых):

| Политика | P | R | F1 | Возврат | Шаги |
|---|---:|---:|---:|---:|---:|
| oracle (максимум) | 0.850 | 0.850 | **1.000** | **+1.000** | 1 |
| сверка (находит всё) | 0.850 | 0.850 | **1.000** | **+0.980** | 11 |
| «пометить всё» | 0 | 0 | 0 | **−1.000** | 7 |
| случайная (угадывание) | 0 | 0 | 0 | **−1.000** | 21 |

- *Реплика:* «Оракул проверяет максимум, а не агента — отдельно от баллов. Наврать нельзя: минус единица».

## 4. Чего НЕ говорить (по ТЗ)

| ❌ Запрещено | Почему |
|---|---|
| «Мы улучшили модель на N%» | Нет контролируемого сравнения на отложенных данных → просто не говорим ничего подобного |
| «Это аудит/аудиторское заключение» | Программная задача; мы не оказываем аудиторских услуг |
| «Наш агент найдёт ошибки лучше бухгалтера» | Мы не ранжируемся по награде агента |
| «Обучили модель на GPU» | Официальная проверка без сети/GPU; обучение необязательно |
| Обещания «в проде за неделю» | Сначала пилот на их данных в их контуре |

## 5. Вопросы жюри и готовые ответы

| Вопрос | Ответ (суть, своими словами) |
|---|---|
| Зачем среда, а не готовый агент? | Таково ТЗ: среда — продукт; жюри оценивает среду и оценщика, а не награду агента |
| Почему не обучали модель? | Необязательно, не даёт баллов, требует GPU/сети. Среда готова к обучению: интерфейс, траектории, награда — политика может учиться снаружи |
| Как вы защитились от подгонки под скрытые seed? | Оси конфигурации + канонизация ID + парные проверки; типы ошибок опубликованы заранее; «одних seed недостаточно» — поэтому осей много (валюты, пояса, размеры, порядок, имена) |
| Что если у жюри другие, «странные» сочетания параметров? | Ровно это мы и гоняли: слепая проверка на 20 неиспользованных seed'ах с экзотикой (одна валюта, без дистракторов, clean+сценарии) — нашла и починила 3 мины ядра. И марафон 10 подряд |
| Как понять, что доказательства достаточны? | Тест: из КАЖДОГО полного набора доказательств сумма пересчитывается независимо; файл — tests/test_evidence_sufficiency |
| Сколько ресурсов? | 28 МБ памяти из 4096, эпизод 0.03 с из 60, решение 9 МБ из 1024, 2 ядра — замерено в CI и марафоне |
| Что с реальными данными клиента? | Продукт работает на синтетике в своём контуре; при необходимости — их сервер, без сети; это и есть аргумент безопасности |
| Сколько багов вы нашли сами? | 18 записей в журнале сбоев — как поймано, метрика, фикс (docs/ARCHITECTURE.md §12) |
| Сколько это стоит / как внедрять? | Пилот: описать их правила (2–3 дня) → адаптация профиля → прогон их проверяющего → контейнер в их контур; дальше лицензия + поддержка |
| Что самое сложное было? | Не код, а честность: сделать так, чтобы эталон описывал реальное расхождение и чтобы его было нельзя угадать |
