## По типам ошибок (кто что находит и что теряет)

Один и тот же эталон, разложенный по четырём типам: полнота (recall) показывает, какие ошибки политика действительно ловит. Сырые значения: `artifacts/diagnostics_by_type.csv`.

**Как читать разбивку:**

- `oracle` обязан давать полноту 1.00 по всем четырём типам — это проверка, что среда вообще допускает максимум награды для каждого типа.
- `reconciliation` показывает, что алгоритмическая сверка закрывает все четыре типа без пропусков (включая сценарии S1/S2, где две ошибки делят один платёж).
- `mark_all` и `random` дают 0.00 по всем типам: ни угаданный ID, ни «пометить всё» не считаются находкой без полного комплекта доказательств.
- Сложность взаимодействия видна в тестах, а не в этой таблице: наивный детектор по датам ловит `period_cutoff` и теряет вторую ошибку того же платежа (`test_naive_date_only_detector_misses_the_other_errors`).


## Как читать

- **oracle** — отправляет эталон с доказательствами: проверяет, что **максимум награды достижим** (F1 = 1.0). Это проверка среды, не агента.
- **reconciliation** — простой алгоритм сверки: находит все ошибки без ложных срабатываний (FP = 0, FN = 0) и молчит на чистых эпизодах.
- **mark_all** — атака «пометить всё»: F1 = 0 и возврат −1 на эпизодах с ошибками; на чистых она получает штраф за ложные обвинения.
- **random** — случайный исследователь: угаданные ID не дают TP (нужен полный комплект доказательств).
