# Записка о дизайне — FinRepGYM

> Краткое описание устройства среды (пункт сдачи «Записка о дизайне»).
> Версия 0.1 · 20.11.2026 · подробный разбор: `docs/ARCHITECTURE.md`, правила: `docs/RULES.md`.

## 1. Что это и каковы границы продукта

**FinRepGYM** — воспроизводимая среда для дообучения и проверки ИИ-аудитора:
синтетическая компания → инструменты расследования → скрытые финансовые ошибки →
ответ с доказательствами → объективная награда.

Вне наших компетенций: обучение весов (необязательно и не даёт баллов; среда веса
не обновляет), платёжные приложения, чат-боты, один аудиторский отчёт, реальные
финансовые данные, сеть/платные API/GPU при проверке.

## 2. Пять подсистем

| Подсистема | Файл | Назначение |
|---|---|---|
| Генератор | `generator.py` | скрытая история → документы → причинные мутации → эталон и провенанс |
| Среда | `env.py` | контракт `reset/step`, 5 действий, лимиты, режимы train/eval, изоляция |
| Оценщик | `matcher.py`, `reward.py` | сопоставление находок с эталоном, P/R/F1, терминальная награда |
| Политики | `policies.py` | 4 адаптера: сверка, оракул, «пометить всё», случайная |
| Преобразования | `transforms.py` | безвредные перестановки и переименование ID (парные проверки) |

Поток: `генератор → файлы эпизода → среда ⇄ политика → оценщик → награда/траектории`.

## 3. Как создаётся эпизод

1. **Правильная бухгалтерия.** Каждое событие даёт пару записей журнала, поэтому
   `Σдебет = Σкредит` и сверка дебиторки с документами истинны **по построению**.
   Сюда же попадают законные отвлекающие случаи: возвраты, разбитые платежи,
   повторяющиеся суммы, неоплаченные счета.
2. **Проверка чистого состояния.** Несовпадение здесь = остановка генерации (это брак,
   а не «сложность»).
3. **Документы.** Выгрузка шести открытых файлов по форматам регламента.
4. **Каузальная мутация.** Ошибка вносится **после** проверки и записывается как
   «что именно изменено» (до/после) в закрытый провенанс. Мутация всегда порождает
   **декларируемое, вычислимое по открытым файлам расхождение** — эталон описывает
   реальное расхождение, а не подозрительную строку.
5. **Независимая верификация.** Расхождения пересчитываются из открытых файлов и
   сверяются с эффектами мутаций; несовпадение = эпизод не создаётся.

## 4. Изоляция: что видит агент

- **Открытая зона:** `manifest.json`, `ledger.csv`, `invoices.jsonl`, `payments.jsonl`,
  `fx.csv`, `policy.json`.
- **Закрытая зона:** `truth.json`, `provenance.json`, зерно генерации — физически
  отдельно, недоступны через действия; при закрытой проверке оценщик запускается
  отдельным процессом.
- **Наблюдение** содержит только три элемента: запрошенные записи **или** результат
  **или** ограниченную ошибку, плюс остаток шагов. Shell, SQL, файловая система,
  сеть недоступны.
- **Награда** во время расследования всегда 0 (подсказок нет); в режиме `eval` политика
  получает 0 на всех шагах, истинная награда — только у оценщика.
- Лимиты: 100 шагов, 60 секунд (время проверяется до выполнения действия → обрезка
  с пустым ответом), страница ≤ 50 строк, курсоры стабильны.

## 5. Что прячется в эпизодах

**Четыре типа ошибок** (независимо настраиваются, словарь опубликован в манифесте):

| Тип | Расхождение |
|---|---|
| `duplicate_entry` | Σдебет − Σкредит = −сумма продублированной строки |
| `partial_allocation` | документ платежа ≠ распределению в журнале |
| `fx_rate` | конвертированная строка ≠ документ × курсу policy-даты |
| `period_cutoff` | балансAR внутри периода ≠ документам |

**Два сценария взаимодействия** (обязательный пункт): обе ошибки делят **один
кросс-валютный платёж у границы периода**, поля не пересекаются (время vs сумма),
поэтому наивный детектор обязан терять вторую ошибку:
S1 = `fx_rate` + `period_cutoff`; S2 = `partial_allocation` + `period_cutoff`
(«частичный платёж в другой валюте на границе периода»).

**Чистые компании:** правильный ответ — ничего не находить; ложные обвинения штрафуются.

## 6. Обобщение и защита от подгонки

Скрытые эпизоды собирает **жюри**: свои seed + **новые сочетания наших осей конфигурации**
+ безвредные преобразования. Оси: `seed`, `clean`, `issue_types`, `n_issues`, `scenarios`,
размер, валюты, часовые пояса, отвлекающие случаи, порядок и ID записей.

Два защитных механизма:
- **канонизация** (множества ID с сортировкой, верхний регистр валют) делает ответ
  невосприимчивым к порядку и нумерации;
- **парные проверки**: перестановка строк и переименование ID сохраняют ответ оракула
  и награду (20/20 в `check.py`).

## 7. Оценка ответа

Нормализация находки → **взаимно однозначное** сопоставление (тип + канонические ID +
валюта + сумма в допуске + хотя бы один **полный** допустимый набор доказательств) →
P, R, F1 → `reward = clip(2·F1 − 1 − 0.002·шаги, −1, 1)`, только терминальная.

Награда зависит от **полей и доказательств**, а не от текста объяснения. Краевые случаи
F1: оба пусты → 1; эталон пуст, находки есть → 0; нулевой знаменатель → 0.

## 8. Проверяемость одной командой

```bash
python scripts/check.py     # 124 юнит-теста + 32 регламентные проверки
python scripts/organizer_check.py   # репетиция закрытой проверки: 20 эпизодов x 4 политики
```

Свипы (13 seed × 6 конфигураций), атаки, детерминизм (повтор → байт-в-байт), утечки,
парные проверки, часовые пояса. Всё локально и **офлайн**, зависимостей нет вообще.
CI на каждом пуше гоняет то же самое на **Python 3.11** и дополнительно собирает
контейнер (`docker run --rm finrepgym` — та же проверка внутри образа).

Диагностика по 4 политикам: `docs/DIAGNOSTICS.md`.

## 9. Честные ограничения

1. Обучение весов **не выполнялось и не заявляется**; среда веса не обновляет — она
   даёт задания и оценки.
2. Награда доказывает корректность среды, **не пригодность для реального аудита**.
3. Все данные **вымышленные**; реальные финансовые данные не поддерживаются
   (это и есть аргумент безопасности для пилотов).
4. Проверка проходит **без сети, платных API и GPU**; Python 3.11+, только stdlib.
5. В скелете оценщик работает в том же процессе, что и среда (политике недоступен);
   при закрытой проверке запускается отдельным процессом — задокументировано.
6. Реализовано 4 типа ошибок из 4 требуемых; расширение типов — только по заказу
   и вне рамок регламента (типы известны заранее).
7. Официальная проверка — не профессиональское аудиторское заключение.
