# FAQ для жюри: короткие ответы на вероятные вопросы

Каждый ответ — факт + чем доказан (команда или тест). Всё воспроизводится офлайн.

| # | Вопрос | Ответ | Чем доказано |
|---|---|---|---|
| 1 | Как быстро проверить решение одной командой? | `python scripts/check.py` — 32 проверки (свипы, атаки, детерминизм, утечки, парные, пояса, лимит времени) + 194 юнит-теста; точка входа оценщика — `judge_adapter.py`; либо `docker run --rm finrepgym` — то же внутри контейнера | `scripts/check.py`, `judge_adapter.py`, `Dockerfile`, CI |
| 2 | Данные действительно одинаковы на любом железе? | Да. Деньги — целые минимальные единицы, курсы — десятичные строки, округление half-up, всё детерминировано зером. Отпечаток эпизода (seed=42) — одна константа на Windows, Linux, macOS и на Python 3.11/3.12 | `python scripts/golden_hash.py`, `tests/test_golden.py`, CI-матрица 3 ОС x 2 версии |
| 3 | Эталон — это реальное расхождение или «подозрительная строка»? | Реальное: сначала строятся сбалансированные книги, затем вносится причинная мутация с записью «до/после»; заявленная сумма равна наблюдаемой разнице в открытых файлах | `_verify_declared` в генераторе, `test_declared_discrepancy_matches_open_records`, независимый пересчёт 20/20 в `jury_conditions.py` |
| 4 | Может ли агент наврать и получить награду? | Нет. TP требует точного совпадения типа, множества ID (лишний ID убивает совпадение), валюты (регистр не склеивается), суммы (τ=0) и **полного** набора доказательств из **существующих** ID. «Пометить всё» = −1, угаданный ID = 0, дубликаты = FP, несуществующий evidence_id = FP | `tests/test_attacks.py`, `tests/test_metrics.py`, `test_nonexistent_evidence_id_is_fp_not_tp` |
| 5 | Награда пригодна для обучения? | Да: монотонна по качеству ответа (каждая верная находка повышает, каждая ложная/недоказанная снижает), терминальна, ограничена [−1, 1], детерминирована. `inspection_steps` считается до `submit` (submit не в штрафе): F1=1 при 0/10/50/100 шагах → 1.00/0.98/0.90/0.80. Обучение весов сознательно не делали | `tests/test_metrics.py::TestRewardMonotonicity`, `judge_adapter.test_inspection_steps_shift_the_reward_exactly` |
| 6 | Где оракул? Почему его нет в траекториях? | Оракул — инструмент оценщика (спека 06: «Oracle только для оценщика»). Он проверяет, что максимум награды достижим, и живёт в диагностике, а не в обучающих траекториях | `docs/DIAGNOSTICS.md`, `artifacts/diagnostics.csv` |
| 7 | Есть ли утечки эталона в наблюдения, `info` или объяснение награды? | Нет: наблюдения проходят сканером по списку запрещённых токенов; `info` в `reset` — `{mode, steps_used, schema_version}`, в `step` — `{mode, steps_used}`, закрытая зона отделена от открытой | сканер в `build_trajectories.py`, `tests/test_contract.py`, `tests/test_isolation_writes.py` |
| 8 | Среда что-нибудь пишет на диск во время прогона? | Ничего: полный прогон (чтение всех таблиц, калькулятор, вредоносные команды, submit) не меняет ни одного байта папки эпизода и не создаёт файлов | `tests/test_isolation_writes.py` |
| 9 | А если агент сойдёт с ума — среда упадёт? | Нет: 500 случайных и вредоносных действий (SQL-инъекции, `__import__`, null, огромные лимиты, мусор вместо объекта) дают ограниченную JSON-ошибку, бюджет шагов не превышается | `tests/test_fuzz.py` |
| 10 | Что если взять свои seed и свои сочетания параметров? | Работает: слепая проверка на свежих seed 97001–97020 и новых сочетаниях — 9/9; марафон из 10 полных оценок жюри подряд — 10/10 (200 свежих эпизодов) | `scripts/jury_conditions.py`, `scripts/jury_marathon.py`, `scripts/organizer_check.py --seeds` |
| 11 | Ресурсы в пределах регламента? | Пик памяти 25–31 МБ из 4096 (марафон: 27 МБ, бенчмарк: 31 МБ); самый долгий средний прогон эпизода 0.073 с из 60 (запас ×1046); размер решения ~9 МБ из 1024; 2 CPU-ядра; без сети и GPU | `python scripts/benchmark.py`, `artifacts/benchmark.csv`, `artifacts/jury_marathon.md` |
| 12 | Порядок строк или ID влияет на ответ? | Нет: перестановка строк и смена ID сохраняют находки и награду до 12 знаков; порядок находок в `submit` тоже не важен | `transforms.py`, 20 парных проверок в `check.py`, `test_finding_order_does_not_change_metrics_or_reward` |
| 13 | Данные настоящие? | Нет, полностью синтетические (реальные данные запрещены регламентом). Имена, ID, валюты (USD/EUR/KZT), часовые пояса (включая +09:30) и порядок строк варьируются от seed | `docs/RULES.md`, `docs/SCHEMAS.md` |
| 14 | Почему ровно 4 типа ошибок? | Типы заданы регламентом заранее; мы реализовали все четыре и добавили 2 сценария взаимодействия (S1: курс + граница, S2: частичный платёж в другой валюте на границе), где две ошибки делят один платёж — это усложняет анализ, не вводя новых типов | `docs/RULES.md`, `docs/DESIGN_NOTE.md` |
| 15 | Что ломалось в процессе и как вы это мерили? | 18 записей в журнале сбоев: сбой → как обнаружен → метрика → фикс (например, неаддитивность округления конвертации, «молчащий» замер памяти, кириллица в cp1252-консоли, расхождение с опубликованными определениями) | `docs/ARCHITECTURE.md` §12 |
| 16 | Почему проект называется FinRepGYM, а пакет `audit_env`? | FinRepGYM — имя продукта (в заголовках, манифестах, `schema_version: finrepgym/1.0`, образе Docker `finrepgym`); `audit_env` — технический идентификатор Python-пакета | `README.md`, `src/audit_env/__init__.py` |
| 17 | Как жюри подключает вашу среду? | Тонкий адаптер `judge_adapter.py` в корне репозитория (в контейнере — `/app`): `generate_episode(seed, config, output_dir)`, `make_env()` с `reset/step`, `score_episode(episode_dir, findings, inspection_steps)`. Действия приходят конвертом `{"name", "args"}`, наблюдения — в каноническом виде определений | `judge_adapter.py`, `tests/test_judge_adapter.py` (16 тестов), README «Точка входа оценщика» |
| 18 | Что возвращает `score_episode` при битой отправке? | `{"return": -1, ...все метрики null}` и запись в журнале оценщика; валидный ответ — `{tp, fp, fn, precision, recall, f1, return}` с точным значением формулы | `judge_adapter.py`, `test_too_many_findings_is_structural_error`, `test_inspection_steps_shift_the_reward_exactly` |

## Чего мы сознательно НЕ делали

- Обучение весов и заявления об улучшении модели (спека: баллов не даёт, а улучшений без контролируемого сравнения заявлять нельзя).
- Пятый тип ошибок (типы известны заранее).
- Реальные данные компаний (запрещено).
- UI/дашборды (баллов не дают, время ушло на доказательства).
- Сетевые вызовы и платные API (официальная проверка проходит офлайн).
