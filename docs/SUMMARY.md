## 1. Что это

**audit-rl-env** — воспроизводимая RL-среда для дообучения и проверки ИИ-аудитора:
синтетическая компания → инструменты расследования → скрытые финансовые ошибки →
ответ с доказательствами → объективная награда.

Сам продукт — **среда и оценщик**, а не агент и не аудиторское заключение.
Обучение весов необязательно, баллов не даёт; жюри оценивает среду и оценщика.

## 5. Журнал разбора сбоев (10 записей, `docs/ARCHITECTURE.md`)

Самые серьёзные:
1. **Эталон дубля указывал одну из двух одинаковых строк** → после перестановки ответ не переносился бы (блок 15 баллов). Теперь эталон указывает пару.
2. **Сохранение и загрузка эпизодов смотрели в разные папки** → упёрлись бы при сдаче.
3. **Лимит времени** проверялся после действия и пропускался из-за гранулярности часов Windows.
4. **Кросс-платёж в базовой валюте** → курс не применялся → не оставалось кандидата для `fx_rate`.
5. **Неаддитивное округление конвертации** `conv(a) − conv(b) ≠ conv(a − b)` → расхождение на 1 единицу (поймано сборкой эпизодов).

Плюс: timedelta-цепочка в генераторе, кодировка вывода cp1251, ключ `"null"` в группировках, мусорная строка при склейке кода, парсинг смещений в минутах.

## 8. Честные ограничения (для записи и защиты)

- Обучение весов не выполнялось и не заявляется; веса среда не обновляет.
- Награда доказывает корректность среды, **не пригодность для реального аудита**.
- Данные полностью вымышленные; реальные финансовые данные не используются и не поддерживаются.
- Официальная проверка проходит без сети, платных API и GPU — зависимостей нет вообще.
- Оценщик в скелете работает в том же процессе; при закрытой проверке запускается отдельным
  процессом (задокументировано как ограничение).
