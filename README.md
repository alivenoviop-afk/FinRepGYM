# audit-rl-env — RL-среда для дообучения моделей финансового аудита

> **Статус: скелет, день 1 (19.11.2026).** Это не сдача. Контракт + 2 типа ошибок из 4.

Воспроизводимый симулятор ИИ-аудитора: синтетические документы компании, инструменты
расследования, скрытые финансовые ошибки, функция награды.

## Запуск одной командой

```bash
python scripts/demo.py          # скриптовая политика на одном эпизоде
python -m unittest discover -s tests -v
```

Зависимости: **только стандартная библиотека Python 3.11+** (официальная проверка без сети).
Локально проверено на Python 3.12, код совместим с 3.11.

## Устройство

```
fintech-audit-rl/
├── src/audit_env/
│   ├── generator.py   # скрытая история -> документы -> причинные мутации -> truth/provenance
│   ├── env.py         # контракт reset/step, действия, лимиты, изоляция
│   ├── matcher.py     # нормализация, взаимно однозначное сопоставление, P/R/F1, валидация submit
│   └── reward.py      # clip(2*F1 - 1 - 0.002*steps, -1, 1)
├── scripts/demo.py    # базовая скриптовая политика
└── tests/             # контракт, награда, атаки, утечки, воспроизводимость
```

### Открытые файлы эпизода (видны агенту)
`manifest.json`, `ledger.csv`, `invoices.jsonl`, `payments.jsonl`, `fx.csv`, `policy.json`

### Закрытые файлы оценщика (агент не видит)
`truth.json`, `provenance.json`, seed. Оценщик работает вне процесса агента;
через интерфейс действий записи доступны только на чтение.

Наблюдения содержат только: запрошенные записи / результат-ошибку / остаток шагов.
Нет shell, SQL, файловой системы, интернета. Награда в эпизоде всегда 0 до завершения.

## Контракт (раздел 04 спеки)

- `reset(seed, config) -> (observation, info)`; первое наблюдение: задача, manifest, краткая политика, бюджет шагов.
- `step(action) -> (observation, reward, terminated, truncated, info)` в стиле Gymnasium; наследование `gym.Env` не требуется.
- Действия: `list_records`, `get_record`, `get_document`, `calculator`, `submit`.
- Страница ≤ 50 строк, курсоры стабильны. Максимум 100 шагов, лимит времени 60 с.
- `submit` -> `terminated=true`. Лимит шагов/времени -> `truncated=true` + пустой итоговый ответ.
- Неизвестный ID/действие -> ограниченная ошибка, шаг расходуется.

## Типы ошибок

Спека требует **четыре независимо настраиваемых типа**. Скелет реализует два (совет раздела 08:
«сначала контракт и два типа ошибок»):

| Тип | Статус | Как детектируется |
|---|---|---|
| `duplicate_entry` — дубли счетов | ✅ есть | Σdebit − Σcredit = сумма продублированной строки |
| `period_cutoff` — ошибка отнесения к периоду | ✅ есть | баланс AR внутри периода ≠ документам |
| `partial_allocation` — пропущенное/частичное распределение платежа | ⬜ день 2 | — |
| `fx_rate` — неверная дата/курс конвертации | ⬜ день 2 | `fx.csv` и `policy.json` уже сгенерированы |

Также реализованы: чистые компании (`clean=true`), отвлекающие случаи (разбитые платежи,
повторяющиеся суммы), 2 типа ошибок с записанным причинным изменением в `provenance.json`.

## Награда и метрики

`reward = clip(2*F1 - 1 - 0.002*inspection_steps, -1, 1)` — только терминальная.

Краевые случаи F1: эталон и выводы пусты → 1; эталон пуст, выводы есть → 0;
нулевой знаменатель у P или R → 0.

## Открытые решения (опубликовать в сдаче)

1. **Нормализация:** тип — точное совпадение строки; `affected_ids` — множество строк, сортируется;
   валюта — верхний регистр; сумма — целые минимальные единицы.
2. **Сопоставление:** жадное, в порядке подачи находок; каждой находке назначается первая
   не занятая эталонная ошибка, прошедшая все проверки (тип, IDs, валюта, допуск, полный
   допустимый набор доказательств). Повторная находка по тому же эталону → FP.
3. **Допуск:** `amount_tolerance_minor` из `truth.json` (пока 0).
4. **Truncated:** при исчерпании бюджета эпизод получает награду, посчитанную для **пустого**
   ответа, а не 0 — иначе политика могла бы уходить в тайм-аут ради избежания штрафа
   (спека: «пустой итоговый ответ»). Режим настраивается: `truncation_reward="score_empty"|"zero"`.

## Честные ограничения скелета

- Реализовано 2 типа ошибок из 4.
- Одна валюта (USD); мультивалютность и курсы готовы структурно, но в ошибках не участвуют.
- `n_invoices=80` даёт ~270 проводок (в диапазоне 200–2000); диапазон 20–200 документов
  достигается конфигом.
- Награда не доказывает пригодность для реального аудита.
