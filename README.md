## Точка входа оценщика: `judge_adapter.py`

Единый способ подключения (определения проверок от 20.11.2026). Рабочая
директория — **корень репозитория** (в контейнере это `/app`); самопроверка
точки входа: `python judge_adapter.py`.

```python
from judge_adapter import generate_episode, make_env, score_episode

# 1) эпизод в каталоге жюри: manifest, ledger, invoices, payments, fx, policy
#    + закрытые truth и provenance
generate_episode(seed, config, output_dir)

# 2) среда с каноническим протоколом
env = make_env()
obs, info = env.reset(seed=seed, config={"mode": "closed",          # или "train"
                                         "episode_dir": "<каталог>",
                                         "team_config": {...}})     # настройки генератора
obs, reward, terminated, truncated, info = env.step(
    {"name": "list_records", "args": {"table": "ledger", "cursor": None, "limit": 50}})

# 3) закрытая оценка ответа (только процесс жюри)
report = score_episode(episode_dir, findings, inspection_steps)
```

**Схема результатов (канонический вид):**

- первое observation: `{"task", "manifest", "policy", "remaining_steps": 100}`;
- далее: `{"result", "error", "remaining_steps"}` — незаполненное поле равно `null`;
- `list_records` → `{"records": [...], "next_cursor": str|null}` (первый курсор — `null`,
  страница ≤ 50, курсоры стабильны: повторный запрос той же страницы даёт те же строки);
- `get_record`/`get_document` → объект записи/документа; `calculator` → десятичная строка
  (`0.1+0.2` → `"0.3"`); `submit` → `{"accepted": true}` либо ограниченная ошибка;
- шаг после завершения → ошибка `episode_finished`, состояние и награда не меняются;
- `score_episode` → `{tp, fp, fn, precision, recall, f1, return}`; невалидная структура
  (31 находка, 11 доказательств, explanation > 1000 символов и т.п.) → `return = -1`,
  остальные поля `null` + запись в журнале оценщика;
- в закрытом режиме `reward` политики всегда числовой `0` (включая завершение);
  истинная награда хранится только на стороне оценщика.

**Гарнитура оценщика (детерминированный C18):** в `config` reset можно передать
`"time_limit_s": 0` — эпизод завершится по лимиту времени без «медленного
ноутбука»: `truncated = true`, код ошибки `time_limit`, пустой итоговый ответ.
Поле нужно только процессу оценщика; политике оно не передаётся.

**Соответствие четырёх типов ошибок:** адаптер не переименовывает типы — имена в
`truth.json`, `policy.json`, находках и действиях среды совпадают: `duplicate_entry`,
`period_cutoff`, `partial_allocation` (варианты «частичный»/«пропуск» задаются
настройкой `partial_variant`), `fx_rate`. Переводить названия полей адаптеру не нужно.

## Эпизоды, траектории и диагностика

**Эпизоды (пункт сдачи «10 train + 10 dev»).** Раскладка: train = 2 чистых + 4 одиночных
(все 4 типа) + 2 парных + 2 сценария; dev = 1 чистый + 4 одиночных + 3 парных + 2 сценария.
Размеры 228–348 проводки, 110–160 документов, 0–2 ошибки — в рамках спеки.
Каждый эпизод **проверяется до записи**: оракул получает F1 = 1.0, сверка даёт FP = 0 и
FN = 0, в открытых файлах нет закрытого эталона. Seed'ы и конфиги — в `episodes/registry.json`.
Это **открытые** эпизоды (их правда лежит рядом); закрытые жюри собирает своими seed'ами
из наших осей конфигурации — в репозиторий они не попадают.

**Траектории (пункт сдачи `trajectories.jsonl`).** Диагностика покрывает 20 эпизодов ×
4 политики = 80 прогонов; в сами траектории входят **60 прогонов трёх «агентских»
политик** (reconciliation, mark_all, random — 846 записей), потому что спека требует:
«**Oracle только для оценщика**» (его прогоны — в диагностике, проверка максимума).
Поля: `episode_id, policy, step, action, observation, reward, terminated, truncated, info`
(в `info` — только `mode`, `steps_used` и в reset `schema_version`: закрытых данных нет).
Наблюдения проверены сканером: закрытого эталона в них нет.

**Диагностика (требование спеки «P, R, F1, возврат, шаги и время»)** — `docs/DIAGNOSTICS.md`
и `artifacts/diagnostics.csv`:

| Политика | P | R | F1 | Возврат | Шаги | Время |
|---|---:|---:|---:|---:|---:|---:|
| oracle | 0.850 | 0.850 | **1.000** | **+1.000** | 1.0 | 0.005 |
| reconciliation | 0.850 | 0.850 | **1.000** | **+0.980** | 11.1 | 0.006 |
| mark_all (атака) | 0.000 | 0.000 | 0.000 | −1.000 | 7.2 | 0.002 |
| random (угадывание) | 0.000 | 0.000 | 0.000 | −1.000 | 21.0 | 0.004 |

P и R усреднены по всем 20 эпизодам (3 чистых дают 0 по построению, если эталон
пуст и находок нет); F1 усреднён отдельно и равен 1.0 у оракула и сверки.
Оракул доказывает достижимость максимума; сверка находит всё без ложных
срабатываний; атаки не получают выгоды.

### Открытые файлы эпизода (видны агенту)
`manifest.json`, `ledger.csv`, `invoices.jsonl`, `payments.jsonl`, `fx.csv`, `policy.json`

### Закрытые файлы оценщика (агент не видит)
`truth.json`, `provenance.json`, seed. Оценщик работает вне процесса агента;
через интерфейс действий записи доступны только на чтение.

Наблюдения содержат только: запрошенные записи / результат-ошибку / остаток шагов.
Нет shell, SQL, файловой системы, интернета. Награда в эпизоде всегда 0 до завершения.

## Контракт (раздел 04 спеки)

- `reset(seed, config) -> (observation, info)`; первое наблюдение: задача, manifest, краткая политика, бюджет шагов.
- `step(action) -> (observation, reward, terminated, truncated, info)` в стиле Gymnasium; наследование `gym.Env` не требуется.
- Действия: `list_records`, `get_record`, `get_document`, `calculator`, `submit`.
- Страница ≤ 50 строк, курсоры стабильны. Максимум 100 шагов, лимит времени 60 с.
- `submit` -> `terminated=true`. Лимит шагов/времени -> `truncated=true` + пустой итоговый ответ.
- Неизвестный ID/действие -> ограниченная ошибка, шаг расходуется.

## Типы ошибок

Спека требует **четыре независимо настраиваемых типа**. **Реализованы все четыре:**

| Тип | Статус | Как детектируется |
|---|---|---|
| `duplicate_entry` — дубли счетов | ✅ есть | Σdebit − Σcredit = −сумма продублированной строки |
| `period_cutoff` — ошибка отнесения к периоду | ✅ есть | баланс AR внутри периода ≠ документам |
| `partial_allocation` — пропущенное/частичное распределение платежа | ✅ есть | документ платежа ≠ распределению в журнале; AR завышен на недостающую сумму |
| `fx_rate` — неверная дата/курс конвертации | ✅ есть | конвертированная строка кросс-валютного платежа ≠ документ × policy-курс |

**Мультивалюта:** три валюты (USD/EUR/KZT), документы в своей валюте, кросс-валютные платежи
постятся в базовую; курс — `policy.fx_rate_date` из `fx.csv`; сравнение разных валют без
конвертации запрещено правилом `policy.json`.

Также реализованы: чистые компании (`clean=true`), обязательные отвлекающие случаи
(разбитые платежи, **возвраты**, повторяющиеся суммы, неоплаченные счета),
**два сценария взаимодействия** (S1: `fx_rate`+`period_cutoff`; S2: частичный платёж
в другой валюте на границе периода — `partial_allocation`+`period_cutoff`; обе ошибки
делят один платёж), ошибки с записанным причинным изменением в `provenance.json`
и независимой верификацией заявленного расхождения из открытых файлов.

## Награда и метрики

`reward = clip(2*F1 - 1 - 0.002*inspection_steps, -1, 1)` — только терминальная.

`inspection_steps` — число исследовательских действий **до** `submit` (включая
ошибочные). Сам `submit` входит в лимит 100 действий, но в штраф не входит.
Контрольные значения формулы (определения 20.11, блок 3): F1=1 и 10 шагов → 0.98;
0 шагов → 1.00; 50 → 0.90; 100 → 0.80; F1=2/3 и 10 шагов → 47/150 ≈ 0.31333;
F1=1/2 и 10 шагов → −0.02; F1=0 → −1 после clip.

Краевые случаи F1: эталон и выводы пусты → 1; эталон пуст, выводы есть → 0;
нулевой знаменатель у P или R → 0.

## Открытые решения (опубликовать в сдаче)

1. **Нормализация:** тип — точное совпадение строки; `affected_ids` — множество точных
   строк (порядок и повторы не важны, лишний ID убивает совпадение); `currency` —
   **точное совпадение, регистр и пробелы не склеиваются**; сумма — целое в
   минимальных единицах (`bool` не принимается).
2. **Сопоставление:** **максимальное паросочетание** (жадный выбор первого совпадения
   запрещён определениями), детерминированный выбор: эталоны идут по возрастанию
   `issue_id`, каждый берёт наименьший индекс входного findings, который ещё позволяет
   достичь максимальной кардинальности. Повторная находка по тому же эталону → FP.
3. **Допуск:** по умолчанию τ = 0 (точное сравнение целых); ненулевой τ допустим,
   только если явно объявлен в `truth.json` для конкретного правила (сейчас 0 везде).
4. **Доказательства:** `evidence_ids` — множество ≤ 10; для TP нужно полное включение
   хотя бы одного допустимого набора; **несуществующий/недоступный ID делает находку
   FP** (существование проверяется по открытым файлам эпизода).
5. **Truncated:** при исчерпании бюджета эпизод получает награду, посчитанную для **пустого**
   ответа, а не 0 — иначе политика могла бы уходить в тайм-аут ради избежания штрафа
   (спека: «пустой итоговый ответ»). Режим настраивается: `truncation_reward="score_empty"|"zero"`.

## Честные ограничения скелета

- **Все четыре типа ошибок реализованы**; типовой потолок `n_issues` — 12.
- Три валюты (USD/EUR/KZT): документы в своей валюте, кросс-валютные платежи постятся
  в базовую; курс policy-даты (`period_end`) из `fx.csv`, округление half-up.
- `n_invoices=80` даёт ~340–350 проводок (в диапазоне 200–2000); диапазон 20–200 документов
  достигается конфигом.
- Награда не доказывает пригодность для реального аудита.
